# System design rationale

The runtime path is **React → FastAPI → shared retrieval and triage services**. The six-stage notebook calls the modular stage interfaces to expose intermediate values. These entry points serve different purposes while sharing the same architectural vocabulary. The [editable architecture](figures/block_diagram/complete_system_architecture.drawio), [application contract](../../application/APPLICATION_GUIDE.md), and [Stage 4 experimental rationale](../../research/stage_4/study_reference/EXPERIMENTAL_RATIONALE.md) describe the design, executable interface, and scientific evaluation.

Keeping [`research/`](../../research/RESEARCH_GUIDE.md) separate places hypotheses, protocols, notebooks and aggregate evidence together. It gives readers a path to assess the Stage 4 contribution independently of the runtime interfaces. The application packages the executable interfaces and deployment contract. The [shared backbone and configurations](../../shared) provide a single implementation for reuse by both workflows. Large model weights, input images and case-level results remain local artifacts. Bundled aggregate tables let readers inspect the measured outcomes without possessing those artifacts.

## Application directories and responsibilities

| Directory | Responsibility | Engineering reason and trade-off |
| --- | --- | --- |
| [`application/medical_dashboard/`](../../application/medical_dashboard) | React renders requests and results. FastAPI parses requests, matches uploads to catalog entries and calls the application services. | A browser/backend boundary keeps model dependencies, file paths and index state in a Python process. This permits API tests with synthetic uploads and lets the UI change independently of the numerics. Two processes introduce a local startup and proxy dependency. |
| [`application/uncertainty_aware_retrieval/`](../../application/uncertainty_aware_retrieval) | Supplies gallery loading, segmentation artifact lookup, uncertainty decisions, embedding preparation, PABP search, and visualization helpers. It also provides CLI and Streamlit entry points. | Reusing the same gallery and decision services avoids maintaining a separate search and policy implementation for each interface. The CLI provides batch preparation without browser interaction. Streamlit provides an alternate inspection interface. |
| [`application/stages/`](../../application/stages) | Exposes input, routing, backbone, triage, retrieval and output modules for the [six-stage notebook](../../research/notebooks/01_complete_system_pipeline.ipynb). | Explicit intermediate contracts make it possible to exercise mask, entropy, acceptance, and retrieval behavior independently. The synthetic Stage 3 adapter makes the walkthrough accessible without a segmentation checkpoint. Its results describe orchestration. The evaluated Stage 4 metrics come from [saved experiment outputs](../../research/stage_4/experiments/RESULTS_GUIDE.md). |

React supplies the browser UI components, and FastAPI supplies request parsing and the HTTP API. The code reuses those frameworks with local interfaces for image artifacts and search. [React documentation](https://react.dev/learn) · [FastAPI documentation](https://fastapi.tiangolo.com/).

The principle is to group a decision with the code that owns it and expose only the information its callers need. For example, the UI consumes an API decision and mask, and the retrieval engine consumes embeddings and eligibility metadata, so neither has to reproduce the entropy calculation. The application services and walkthrough have distinct entry points and adapters. Their contracts and regression tests are the evidence for the behaviors they share. [Parnas, *On the Criteria To Be Used in Decomposing Systems into Modules* (1972)](https://doi.org/10.1145/361598.361623).

## Reproducible serving and storage

- **Precompute the expensive artifacts.** Freeze the model outputs as a binary PNG mask and raw floating-point entropy. The same artifacts feed the study and the application, so switching among aggregators or reloading the UI does not repeat stochastic inference. Match uploads by a digest of image dimensions and decoded RGB pixels. This tolerates filename changes and lossless re-encoding while limiting artifact reuse to the same raster. Lossy transcoding or resizing can change the pixels. [Segmentation runner](../../shared/medclipseg/test.py) and [upload matcher](../../application/medical_dashboard/backend/main.py).
- **Make image/vector association explicit.** Join supplied vectors to the manifest using a unique `image_id@dataset` key before indexing. An array shape of `(N, 512)` establishes dimensions and cardinality. Case keys establish row identity. The loader rejects missing, duplicate or nonmatching keys and nonfinite or zero vectors. The generated cache also uses the configured checkpoint and image paths, file sizes and modification times in its signature. Supplied vectors still require matching encoder and preprocessing provenance. [Catalog and embedding loader](../../application/uncertainty_aware_retrieval/uncertainty_aware_retrieval/embedding_extractor.py) and [custom-gallery API tests](../../application/medical_dashboard/backend/tests/test_api.py).
- **Export the catalog and build one index per serving process.** CSV plus keyed NumPy arrays provides a portable boundary around a relational or file-based source. It keeps credentials and vendor-specific query logic outside the application. The API initializes a single in-memory index on its first gallery request and uses a lock to avoid concurrent initialization. A gallery update requires a restart. The index is a read-mostly research implementation with no claim of database transactions, online index updates, audit logging or multi-tenant scaling. [Application guide](../../application/APPLICATION_GUIDE.md) and [backend initialization](../../application/medical_dashboard/backend/main.py).
- **Keep the configuration replayable.** The two front ends use the same service methods and the research runners record split, seed and frozen thresholds. The tests exercise invariants such as empty-mask fallback, exact-match lookup, vector joins across different row orders and self-exclusion. A fixed seed helps reproduce a local run. Model artifacts, package versions and device details determine cross-platform reproducibility. [Research results](../../research/stage_4/experiments/RESULTS_GUIDE.md) and [PyTorch reproducibility notes](https://docs.pytorch.org/docs/stable/notes/randomness.html).

## Vector search and predicate-aware block pruning

### Representation, metric and baseline

The gallery stores 512 components per image from the UniMedCLIP ViT-B/16 visual path. An encoder trained on medical image–text pairs provides a domain-relevant feature representation. Its visual similarity may reflect lesion appearance, anatomy or acquisition characteristics, and its suitability as a measure of diagnostic relevance requires an independent assessment. The study evaluated selection quality in Stage 4. [UniMedCLIP, Khan et al.](https://arxiv.org/abs/2412.10372) and [local embedding extractor](../../application/uncertainty_aware_retrieval/uncertainty_aware_retrieval/embedding_extractor.py).

For nonzero vectors, L2-normalization gives `q̂ = q/‖q‖₂` and `v̂ = v/‖v‖₂`. Then `cos(q,v) = q̂ᵀv̂` and `‖q̂−v̂‖₂² = 2−2q̂ᵀv̂`. Ranking by descending inner product therefore matches ranking by ascending Euclidean distance on the unit sphere. Dense exact search over the `m` eligible vectors is an inspectable reference with `O(md)` arithmetic for dimension `d`. At 542 cases, the `float32` vector payload is 1,110,016 bytes, about 1.06 MiB. Index blocks, metadata and the serving process use additional memory. Exact filtering is a plausible baseline at this scale. IVF and PABP expose the mechanics of a filtered vector workload and provide measurable candidate and block counters. [Douze et al., *The Faiss Library*](https://arxiv.org/abs/2401.08281) and [retrieval tests](../../application/uncertainty_aware_retrieval/tests/test_pabp_engine.py).

### Pruning correctness and limits

Let `P(v)` be true when a gallery case is accepted by the Stage 4 policy. Within each IVF list, the engine stores the Boolean summary `S(B) = ORᵥ∈B P(v)` for each block. If `S(B)` is false, every vector in the block fails the predicate, so skipping it preserves the eligible top-K **within the probed lists**. For a retained block, the engine checks individual eligibility and excludes the query's case key before computing the inner product. A size-K min-heap retains the best candidates with `O(log K)` work per update. Filtering before scoring avoids spending top-K positions on ineligible candidates. [PABP source project](https://github.com/Fergarciamedina/pabp-filtered-ivf), [application implementation](../../application/uncertainty_aware_retrieval/uncertainty_aware_retrieval/pabp_engine.py), and [Patel et al., *ACORN*, for related filtered vector search](https://arxiv.org/abs/2403.04871).

IVF probes a subset of the available lists by default, so an eligible nearest neighbor can be in an unprobed list. The application defaults request eight lists, four probes and 16 vectors per block. These are engineering defaults. More probes expand the candidate set and increase search work. Small blocks can isolate ineligible cases with finer granularity but introduce more summaries and loop overhead. Larger blocks have a higher chance of containing at least one eligible case and therefore being scanned. The use of flat vectors within the lists keeps scoring exact on the candidates that survive these checks and avoids quantization error in that step. [Johnson, Douze and Jégou, *Billion-scale similarity search with GPUs*](https://arxiv.org/abs/1702.08734) and [local configuration](../../application/uncertainty_aware_retrieval/uncertainty_aware_retrieval/config.py).

The full-probe regression tests compare against exact filtered search on sampled queries. For a query, counters distinguish vectors in pruned blocks, candidates filtered in scanned blocks, self-exclusions, and computed distances. Their sum equals the number of candidates in probed lists. This demonstrates saved candidate distance operations under the predicate. It does not establish latency or recall advantages at the default probe depth. A performance comparison would measure filtered Recall@K against exact prefilter, p50/p95 latency, build time and peak memory over gallery size, predicate selectivity, and `nprobe`. Clinical retrieval quality would additionally need a reference definition of relevant cases and blinded annotations. [Retrieval tests](../../application/uncertainty_aware_retrieval/tests/test_pabp_engine.py) and [FAISS search trade-offs](https://arxiv.org/abs/2401.08281).
